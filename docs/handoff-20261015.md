## 另一台 Windows 电脑的继续方式

检出上述分支后，先按 README 准备 Rust、Tauri、Node 和浏览器测试依赖，
再运行上面的验证命令。需要新的安装器时重新执行 Tauri build。

生成全新的可丢弃合成数据：

```powershell
cargo build --locked -p sessionatlas-cli --release
python scripts/Prepare-NativeReviewFixture.py --help
```

按该脚本的帮助传入新的 artifact 根目录和 release CLI 路径。脚本会创建两个
真实临时 Git 仓库、合成 Codex 历史、无网络/无认证的 `acceptance-tui` 测试工具，
并运行隔离扫描。它拒绝复用非空 fixture 目录。不要把测试工具当成真实 AI 提供商。

启动桌面验收时，`SESSIONATLAS_HOME` 指向 fixture 根目录；测试工具目录放在
该进程的 PATH 前部。WebView2 使用独立的 `WEBVIEW2_USER_DATA_FOLDER`。
这些变量仅对验收进程设置，不修改用户级或系统级环境变量。
扫描器所需的 Pi 目录也应指向 fixture 下的空目录，避免使用实际用户数据。

MSI payload 可通过 `scripts/Inspect-MsiPayload.py` 只读提取。
`Capture-NativeBaseline.py` 只记录本机数据文件元数据/哈希和安装元数据；
`Verify-NativeReviewEvidence.py --help` 提供当前两项目 fixture 的交叉核验用法。
这些脚本不替代原生交互检查。
